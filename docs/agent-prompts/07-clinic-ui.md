## Build (feature folders `presentation/{bloc,pages,widgets}`, `domain`, `data`)
- `auth`: A01 as role entry (doctor) via `POST /api/login`.
- `queue` (D01): `QueueCubit`; list with StatusChip; empty and loading states; red-flag rows open D06, others open D02; refresh.
- `brief` (D02): `BriefBloc` (load, generating, draft, approved, edited, rejected, noGuideline). SOAP sections each labelled "Draft, needs your review" until decided; flags; screenings possibly due with CitationLink (or "No guideline retrieved"); suggested questions; DecisionBar. Edit mode lets the doctor edit text fields and save as `edit`. Provenance line: generated by model + mode, time, reviewer after decision.
- `trust` (D03): side sheet from D02. One TrustRow group per model call: mode, model ID, route/provider, required policy (zdr / confidential), evidence (or "Evidence not exposed by provider"), request ID, latency, outcome (ok / refused / error). A gateway section from the attestation summary: issuer, image digest, source commit, "claims match" (never "verified secure"). GLM route labels exactly: "Zero data retention (operator-declared)" and "Provider E2EE not verified". Dev mode shows a warning row.
- `demo` (D05): buttons to run S1–S10 (`POST /api/demo/scenarios/{id}/run`) and a "Run negative test" toggle/button (`POST /api/demo/negative-test`) that shows the refused TrustEvent inline in red with the text "Request refused before inference: no route met the confidential privacy floor. No fallback model was called."
- `red_flag` (D06): rule name, matched fields, time, the urgent message the patient saw, and no brief.
- go_router routes named D01, D02, D03 (sheet), D05, D06; tablet breakpoints are out of scope; desktop first, min width 1024.
